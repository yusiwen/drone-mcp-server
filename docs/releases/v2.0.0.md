# drone-mcp-server v2.0.0

A security release with breaking changes. It replaces the deprecated SSE transport with Streamable HTTP, makes authentication mandatory in HTTP mode, and flips the server to read-only by default.

## Breaking changes

| Change | What to do |
| :--- | :--- |
| `--sse` was renamed to `--http`. The SSE transport is gone: it was removed from the MCP specification and shipped without DNS rebinding protection. | Replace `--sse` with `--http` and use a client that speaks Streamable HTTP. The flag no longer exists, so an unchanged command line fails with `flag provided but not defined: -sse`. |
| HTTP mode refuses to start without `MCP_AUTH_TOKEN` (or `MCP_AUTH_TOKEN_FILE`). The previous behaviour was to serve unauthenticated. | Set `MCP_AUTH_TOKEN` to 32+ random bytes. `--insecure-allow-anonymous` restores the old behaviour for a throwaway local instance, with a warning. |
| The server is read-only by default: only the 18 read-only tools are registered. | Add `--enable-write-tools` (or `MCP_ENABLE_WRITE_TOOLS=true`) to expose the 27 write and destructive tools. |
| Reverse proxies that forward a public `Host` header to a loopback address now receive `403` from the transport's DNS rebinding protection. | Start with `--allowed-hosts <public-host>` (this replaces the loopback heuristic, one flag is enough), or keep the loopback `Host` in the proxy configuration. |
| Requires Go 1.25+; the MCP Go SDK moved from v1.5.0 to v1.8.0. | Update the toolchain used to build from source. |

## Security fixes

- **Fail-closed HTTP authentication.** Missing, malformed or wrong bearer tokens are rejected with `401`. Tokens are compared in constant time over SHA-256 digests and repeated failures from one address are throttled to `429` after 10 attempts per minute. `MCP_AUTH_TOKEN_FILE` supports mounted secrets.
- **Streamable HTTP transport** with the SDK's DNS rebinding protection (loopback connections carrying a non-loopback `Host` are rejected) and cross-site request protection, plus optional `--allowed-hosts` / `--allowed-origins` allowlists.
- **Read/write tool separation.** Every tool carries MCP annotations (`readOnlyHint`, `destructiveHint`, `idempotentHint`) and write tools are hidden unless explicitly enabled, which removes the prompt-injection path to destructive operations in a read-only deployment.
- **Input validation for every tool argument.** Repository identifiers, names, branches, commit refs, deployment targets and build numbers are validated before they reach the Drone API client, which assembles request paths by string formatting. Path traversal and query injection are rejected.
- **Request hardening.** 1 MiB request body cap, header read and idle timeouts, 1 MiB header cap, graceful shutdown, and bounded log values.
- **Log hygiene.** `X-Forwarded-For` / `X-Real-IP` are ignored unless `--trust-proxy` is set, control characters are stripped so request data cannot forge log lines, and tool arguments are never logged.
- **Supply chain.** Every GitHub Action is pinned to a commit SHA, the Docker vulnerability scan now fails the build on critical findings, `govulncheck` gates the release, Dependabot tracks Go modules and actions, and `mcp-publisher` is pinned to v1.8.1 with a verified sha256.
- **Tests.** The repository previously had none. It now has unit tests for the authentication middleware, the `Host` policy, log sanitization, client address handling, input validation and the tool surface, plus an end-to-end security smoke test (`make smoke`, 36 assertions) that runs in CI.

## Upgrade checklist

1. Replace `--sse` with `--http` in scripts, Compose files and client configurations.
2. Export a strong `MCP_AUTH_TOKEN` and configure the client to send `Authorization: Bearer <token>`.
3. Decide whether the deployment needs write tools; leave `--enable-write-tools` off if it does not.
4. Behind a reverse proxy, add `--allowed-hosts <public-host>` or preserve the loopback `Host` header.
5. Set `--trust-proxy` only if a proxy you control rewrites the forwarding headers.
